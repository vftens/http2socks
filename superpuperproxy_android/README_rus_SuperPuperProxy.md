# SuperPuperProxy для Android

Эта папка превращает `SuperPuperProxy.py` (универсальный адаптер
HTTP/HTTPS/SOCKS5 → простой HTTP-прокси для YouTube на Android TV) в
устанавливаемое Android-приложение (`.apk`) со своей иконкой и простым
интерфейсом Start/Stop, собранное на [Kivy](https://kivy.org/) +
[Buildozer](https://buildozer.readthedocs.io/).

## Зачем это нужно

Приставки Android TV с YouTube поддерживают в настройках Wi-Fi только
простой **HTTP**-прокси без авторизации. Если же ваш реальный
вышестоящий прокси — это SOCKS5, HTTPS или HTTP с логином/паролем,
приставка не сможет подключиться к нему напрямую.

SuperPuperProxy решает эту проблему: он поднимает небольшой локальный
HTTP-прокси без пароля (именно такой понимает Android TV) и
перенаправляет весь трафик через ваш настоящий вышестоящий прокси —
любого из поддерживаемых типов.

## Файлы

- `main.py` — обёртка на Kivy с графическим интерфейсом. Позволяет
  выбрать тип вышестоящего прокси (`http` / `https` / `socks5`), хост,
  порт, опционально логин/пароль и локальный порт прослушивания —
  затем запустить/остановить мост кнопками Start/Stop. Мост работает в
  фоновом потоке со своим циклом событий asyncio.
- `icon.png` — сгенерированная иконка приложения (512×512, скруглённая,
  фиолетово-оранжевая).
- `buildozer.spec` — конфигурация сборки Buildozer (имя пакета,
  разрешения, путь к иконке, целевые уровни API, только `arm64-v8a`).

## Сборка APK

Buildozer работает только под Linux (используйте WSL на Windows или
Linux-VM/контейнер).

```bash
# 1. Установите buildozer (внутри WSL/Linux), например в venv
python3 -m venv .venv && source .venv/bin/activate
pip install --upgrade pip
pip install buildozer cython

# 2. Из этой папки `superpuperproxy_android/` соберите debug-APK
buildozer -v android debug
```

При первом запуске скачивается Android SDK/NDK (несколько гигабайт) —
это может занять время. По завершении APK появится в
`bin/superpuperproxy-1.0-arm64-v8a-debug.apk`.

> Если вы уже собирали `http2socks` через Buildozer в WSL, большинство
> системных зависимостей (SDK, NDK, JDK, build tools) уже закэшированы,
> и эта сборка пройдёт значительно быстрее — обычно за пару минут.

## Установка

```bash
# с устройством, подключённым по USB и включённой "USB-отладкой":
buildozer android deploy run logcat
```

…или просто скопируйте `.apk` из `bin/` на устройство и нажмите на него
для установки (предварительно разрешив «Установка из неизвестных
источников»).

## Как пользоваться приложением

1. Запустите **SuperPuperProxy** — либо прямо на самой Android TV
   приставке (если она умеет ставить APK — а умеют почти все), либо на
   любом Android-устройстве в той же локальной сети, что и приставка.
2. Заполните поля:
   - **Upstream proxy type**: `http`, `https` или `socks5`
   - **Upstream proxy host / port**: адрес вашего реального прокси
     (например, тот, которым вы уже пользуетесь — держите его в
     секрете, не публикуйте!)
   - **Username / Password**: только если вышестоящий прокси требует
     авторизацию
   - **Local proxy port**: порт, к которому будет подключаться
     приставка (по умолчанию `8080`)
3. Нажмите **Start**. В строке статуса появится локальный IP устройства
   — именно его нужно указать на YouTube-устройстве.
4. На приставке/Android TV: **Настройки → Сеть → Wi-Fi → (долгое
   нажатие на сеть) → Изменить сеть → Дополнительные параметры →
   Прокси: Вручную**
   - Имя хоста прокси = IP, показанный в статусе SuperPuperProxy
   - Порт прокси = **локальный порт**, который вы указали (например,
     `8080`)
5. Откройте YouTube — теперь его трафик идёт через ваш вышестоящий
   прокси благодаря SuperPuperProxy.
6. Нажмите **Stop**, чтобы остановить мост.

## Замечания

- Требуется разрешение `INTERNET` (уже объявлено в `buildozer.spec`).
- Держите приложение на переднем плане / в недавних — Android может
  «усыплять» фоновые сетевые сокеты через какое-то время. Для
  постоянно работающего моста стоит превратить его в полноценный
  foreground `Service` Android (`android.permissions =
  FOREGROUND_SERVICE` уже запрошено как заготовка для этой доработки).
- Никогда не коммитьте свой реальный адрес прокси и учётные данные —
  оставляйте `UPSTREAM_HOST` как `*.*.*.*` в исходном коде, а реальное
  значение вводите только в полях UI запущенного приложения.
